Two models, one file between them.

You work in Claude Code. This adds a second AI, OpenAI Codex, for two jobs: look at your code with fresh eyes, and do a side task while you keep working. Codex runs in a sandbox and answers with files. Claude reads those files and shows you the result. Nothing in your project changes until you say yes.

What you get

Two jobs, and you can watch both

Second opinion

Fresh eyes on your changes

Say "ask Codex for a second opinion" in Claude Code. Codex reads your changes without touching them and returns a list of problems, each with a file and line. Claude checks every item against the code and tells you which ones are real. Twenty seconds in the demo.

Worker

A side task done in a separate copy

Say "give this task to Codex". Codex does it in a separate copy of your repository and returns a patch. You see the diff and decide. Several workers can run at once.

You can watch

Nothing runs in the dark

Progress lines in the terminal while Codex works, a codex:N counter appended to your own status line (how many Codex agents run right now; installed by default), a live table in a second window.

Two rules of thumb. A task for the worker has to be complete: what to do, where, how to check, what not to touch. Codex does not ask questions, it assumes and lists its assumptions. And every run spends Codex quota, so ask for a review after a real change, not after every typo.

What happens under the hood

Six steps, and every one of them is a file

The two models never talk to each other. Everything between them is a file you can open.

  1. Claude writes a task into a text file.
  2. A script starts Codex in a sandbox: read-only for a review, write access to one separate copy for a worker.
  3. Codex reads the code, may run the tests, and answers with a JSON file in a fixed format.
  4. The script checks the answer, saves it next to the log, and prints the paths.
  5. Claude opens every finding in the code and marks it real or not.
  6. A fix comes back as a patch. Claude shows it and applies it only after you say so.

When something goes wrong

Read the log first

  • The script prints exit: and log: paths. Read the log first.
  • Exit code 2: wrong arguments. 3: Codex answered outside the format, the raw answer is at the json: path. 4 (worker only): branch or worktree already exists, change the label or clean up. 124: time limit.
  • --dry-run prints the exact Codex command and the prompt without running anything.
  • Codex sees only what it is given: the task, the focus, the files to read, and the shared ~/.agents/AGENTS.md. It does not read your ~/.claude/CLAUDE.md; a project CLAUDE.md only when the project has no AGENTS.md (install step 5 turns this fallback on). If it "did not know" something, put it into the focus or the task.
  • Tests without Codex and without cost: bash skills/second-opinion/tests/run.sh and bash skills/codex-worker/tests/run.sh.

Что ты получаешь

Две работы, и обе видно

Второе мнение

Свежий взгляд на твои изменения

Скажи в Claude Code «спроси у Codex второе мнение». Codex читает твои изменения, ничего не трогая, и возвращает список проблем, каждая с файлом и строкой. Claude проверяет каждый пункт по коду и говорит, какие из них настоящие. Двадцать секунд в демо.

Воркер

Побочная задача в отдельной копии

Скажи «отдай эту задачу Codex». Codex делает ее в отдельной копии твоего репозитория и возвращает патч. Ты смотришь дифф и решаешь. Воркеров может быть несколько сразу.

Видимость

Ничего не работает втемную

Строки хода в терминале, пока Codex работает, счетчик codex:N в конце твоей статус-строки (сколько агентов Codex работает прямо сейчас; ставится при установке), живая таблица во втором окне.

Два правила. Задача воркеру должна быть полной: что сделать, где, как проверить, что не трогать. Codex не задает вопросов: он делает допущения и перечисляет их. И каждый запуск тратит квоту Codex, поэтому проси ревью после настоящей правки, а не после каждой опечатки.

Что происходит под капотом

Шесть шагов, и каждый из них это файл

Две модели никогда не разговаривают друг с другом. Все между ними это файл, который можно открыть.

  1. Claude пишет задачу в текстовый файл.
  2. Скрипт запускает Codex в песочнице: только чтение для ревью, запись в одну отдельную копию для воркера.
  3. Codex читает код, может прогнать тесты и отвечает JSON-файлом в фиксированном формате.
  4. Скрипт проверяет ответ, кладет его рядом с журналом и печатает пути.
  5. Claude открывает каждую находку в коде и отмечает, настоящая она или нет.
  6. Исправление возвращается патчем. Claude показывает его и применяет только после твоего слова.

Если что-то пошло не так

Сначала читай журнал

  • Скрипт печатает пути exit: и log:. Сначала читай журнал.
  • Код выхода 2: неверные аргументы. 3: Codex ответил не по формату, сырой ответ лежит по пути json:. 4 (только воркер): ветка или worktree уже есть, смени метку или прибери. 124: лимит времени.
  • --dry-run печатает точную команду Codex и промпт, ничего не запуская.
  • Codex видит только то, что ему дали: задачу, фокус, файлы для чтения и общий ~/.agents/AGENTS.md. Твой ~/.claude/CLAUDE.md он не читает; проектный CLAUDE.md читает, только если в проекте нет AGENTS.md (этот запасной вариант включает шаг 5 установки). Если он чего-то «не знал», положи это в фокус или в задачу.
  • Тесты без Codex и без затрат: bash skills/second-opinion/tests/run.sh и bash skills/codex-worker/tests/run.sh.
