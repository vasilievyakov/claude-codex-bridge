# claude-codex-bridge

[![tests](https://github.com/vasilievyakov/claude-codex-bridge/actions/workflows/tests.yml/badge.svg)](https://github.com/vasilievyakov/claude-codex-bridge/actions/workflows/tests.yml) [![license: MIT](https://img.shields.io/badge/license-MIT-d4ff3f?labelColor=0b0b0c)](LICENSE) [![site](https://img.shields.io/badge/site-vasilievyakov.github.io%2Fclaude--codex--bridge-0b0b0c?labelColor=d4ff3f)](https://vasilievyakov.github.io/claude-codex-bridge/)

[English version](README.md)

claude-codex-bridge дает Claude Code второй ИИ, OpenAI Codex CLI, для двух задач. Он смотрит на твой код свежим взглядом и делает побочную задачу, пока ты работаешь дальше. Codex работает в песочнице и отвечает файлами; Claude их читает, сверяет каждое утверждение с кодом и показывает тебе результат. В проекте ничего не меняется, пока ты не скажешь «да». Статус-строка показывает, сколько агентов Codex работает прямо сейчас. Два скилла, сегмент статус-строки, bash и python3, никаких демонов и сервисов, 378 тестов на фальшивом `codex`.

Его собрал продуктовый человек вместе с Claude Code, а потом разобрал и починил тем же способом, который связка предлагает: агенты ревьюили, настоящие прогоны Codex ломали, человек решал, что считается. Весь след лежит в репозитории и в разделе [Как это сделано](#как-это-сделано).

![bash demo.sh: Codex находит подложенный баг в режиме только чтения, затем воркер Codex исправляет его в отдельном worktree и возвращает патч](docs/media/demo.gif)

## Что ты получаешь

| | |
|---|---|
| **Второе мнение** | Скажи «спроси у Codex второе мнение». Codex читает твои незакоммиченные изменения, ветку, названные файлы или план в песочнице только для чтения и возвращает находки в фиксированном JSON: серьезность, место, сценарий сбоя, доказательство, уверенность. Claude открывает каждую в коде и ставит отметку: подтверждено, опровергнуто, вне задачи или неясно |
| **Воркер** | Скажи «отдай задачу Codex». Codex делает ее в своем git worktree, писать может только в эту папку, сети нет; прогоняет проверки, которые ты назвал, и возвращает патч. Ты видишь diff и решаешь. Воркеров может быть несколько одновременно |
| **Сигнал в статус-строке** | ` \| codex:2` в конце твоей собственной статус-строки Claude Code, пока работают два агента Codex, и ничего, когда Codex простаивает. Ставится при установке; твоя статус-строка остается как есть, дописывается только сегмент |
| **Строки хода** | Пока Codex работает, в терминале Claude видно, что он делает: какие файлы читает, какие команды запускает, их результат, расход токенов |
| **Живая таблица** | `extras/codex-watch.py` во втором окне: все работающие ревьюеры и воркеры, время, последнее событие, свежие результаты |
| **След на диске** | Каждый прогон оставляет промпт, журнал событий, ответ и патч в `~/.cache/second-opinion/` или `~/.cache/codex-worker/`. Модели не разговаривают напрямую; все, что между ними, это файл, который можно открыть |

## Установка

Открой Claude Code и вставь строку:

```
Установи claude-codex-bridge: сначала прочитай https://raw.githubusercontent.com/vasilievyakov/claude-codex-bridge/main/INSTALL.ru.md, затем выполни каждый шаг, подстрой под эту машину, проверь и отчитайся, что изменил.
```

[INSTALL.ru.md](INSTALL.ru.md) написан для агента: он смотрит на машину, подстраивает каждый шаг, проверяет его и отчитывается. Перед правкой любого конфига он делает бэкап и никогда не перезаписывает твои файлы. Человек может пройти те же шаги руками: каждый шаг это команда.

Что происходит, в десяти шагах: проверка версий, клон этого репозитория, ссылки на два скилла в `~/.claude/skills`, один файл инструкций, который читают оба агента (`~/.agents/AGENTS.md`), установка сигнала в статус-строку и его самопроверка, по желанию официальный плагин Codex и живая таблица, тесты, отчет.

Нужны Claude Code, [Codex CLI](https://github.com/openai/codex) 0.150 или новее (проверено на 0.156) с выполненным входом, git и python3. macOS или Linux.

Проверить, что работает: открой новую сессию Claude Code и набери `/second-opinion`. Или запусти демо, около минуты, два запроса к Codex:

```
git clone https://github.com/vasilievyakov/claude-codex-bridge
cd claude-codex-bridge
bash demo.sh
```

Демо создает одноразовый репозиторий с подложенным багом (процент используется как доля), просит Codex о ревью, потом отдает исправление воркеру. Гифка выше это один такой прогон.

## Как пользоваться каждый день

| Что говоришь в Claude Code | Что происходит | Что видишь |
|---|---|---|
| «Спроси у Codex второе мнение по моим изменениям» | Codex ревьюит незакоммиченные изменения, только чтение | Строки хода, потом таблица: каждая находка с вердиктом и вопрос, что чинить |
| «Попроси Codex отревьюить план в docs/plan.md» | То же для документа вместо диффа | Та же таблица |
| «Пусть Codex посмотрит src/billing.py, фокус на округлении» | То же для названных файлов с фокусом | Та же таблица |
| «Отдай Codex задачу: реализуй parse_date в src/dates.py, тесты в tests/test_dates.py, прогони pytest» | Codex работает в своей копии репозитория | Статус, сводка, что он запускал для проверки, diff и вопрос, применять ли |
| «Поспорь с Codex по находке 2: на строке 41 есть проверка» | Продолжается тот же тред Codex | Его ответ |
| «Убери воркер Codex» | Удаляет worktree воркера; ветка с коммитами сохраняется | Подтверждение |

Три правила. Задача для воркера должна быть полной: что сделать, где, как проверить, чего не трогать; Codex не задает вопросов, он предполагает и перечисляет свои допущения. Каждый прогон тратит квоту Codex, поэтому проси ревью после настоящего изменения. Находка остается утверждением, пока Claude не сверит ее с кодом; поэтому ты видишь их уже с вердиктом.

## Видеть, как работает Codex

Установщик добавляет один сегмент к статус-строке, которая у тебя уже есть. Вот он на статус-строке, которая до установки печатала `Opus | ~/my-project | 41.2K`, пока два настоящих агента Codex запускаются и заканчивают один за другим:

![Статус-строка показывает codex:2, потом codex:1, потом ничего, по мере того как два настоящих агента Codex заканчивают работу](docs/media/statusline.gif)

Как это устроено: `install-statusline.sh` сохраняет твой текущий `statusLine.command` в `~/.claude/statusline/base-command` и направляет Claude Code на `statusline-codex.sh`. Тот запускает твою команду без изменений и дописывает ` | codex:N`, пока живы N процессов `codex exec` (`codex:N+srv`, если работает еще и app-server плагина). Детекция через `pgrep` по имени процесса, поэтому считаются ревьюеры, воркеры и все остальное, запущенное как `codex exec`, из npm, Homebrew или скачанного бинарника. `--self-test` запускает поддельный процесс `codex exec` (без запроса к Codex) и ждет `codex:1`; `--uninstall` возвращает твою прежнюю команду.

Для общей картины запусти `python3 extras/codex-watch.py` во втором терминале: таблица в стиле top с работающими процессами Codex и свежими результатами.

## Что происходит под капотом

1. Claude пишет задачу в файл промпта: роль, объем, фокус, что считается находкой, формат ответа.
2. Скрипт запускает `codex exec` и подает промпт через stdin: песочница `read-only` для ревью; для воркера `workspace-write`, ограниченная свежим git worktree, сеть выключена, если ее не попросили.
3. Codex читает код, может прогнать тесты и отвечает JSON, проверенным по схеме (`--output-schema`).
4. Скрипт проверяет ответ, кладет рядом Markdown-версию и печатает пути: `json:`, `markdown:`, `events:`, `log:`, `prompt:`, `thread_id:`, `exit:`.
5. Claude открывает каждую находку в коде и выносит вердикт. Для воркера скрипт снимает worktree в файл патча и печатает команду, которой проверить, что патч применяется.
6. Claude показывает патч и применяет его только после твоего «да». `--resume` продолжает тот же тред Codex, когда хочешь поспорить с находкой.

Полный разбор с настоящим выводом прогона демо: [docs/how-it-works.ru.md](docs/how-it-works.ru.md).

## Где что лежит

Два скилла, каждый в самодостаточной папке: инструкции для Claude, скрипт, формат ответа, тесты.

```
skills/
  second-opinion/
    SKILL.md                 когда и как Claude вызывает ревью, как судит находки
    scripts/second-opinion.sh   собирает промпт, запускает codex exec только на чтение, проверяет, рендерит
    scripts/findings.schema.json  формат ответа, которому Codex обязан следовать
    scripts/progress.py      превращает события Codex в строки хода (один и тот же файл в обоих скиллах)
    tests/run.sh             137 тестов на фальшивом codex в PATH, без сети и без затрат
  codex-worker/
    SKILL.md                 как Claude пишет задачу, читает результат, предлагает патч
    scripts/codex-worker.sh  worktree, песочница, таймаут, снимок патча, resume, cleanup
    scripts/result.schema.json
    scripts/progress.py
    tests/run.sh             241 тест, тот же подход
extras/
  install-statusline.sh      обязательный шаг статус-строки: установка, --self-test, --uninstall
  statusline-codex.sh        оборачивает твою статус-строку и дописывает сегмент Codex
  statusline-segment.sh      сам сегмент, подключается через source в любую bash-статус-строку
  statusline-minimal.sh      полная статус-строка для тех, у кого ее не было
  codex-watch.py             живая таблица процессов и результатов Codex
  AGENTS.template.md         один файл инструкций для обоих агентов
demo.sh                      один настоящий прогон на одноразовом репозитории
INSTALL.md, INSTALL.ru.md    текст установки для твоего агента
docs/                        сайт, разбор, гифки и их сценарии VHS
.github/workflows/tests.yml  оба набора тестов и установщик статус-строки на Ubuntu и macOS
```

Результаты прогонов в твой проект не попадают: в `~/.cache/second-opinion/` и `~/.cache/codex-worker/` лежат промпт, журнал событий, ответ и патч каждого прогона.

## Если что-то пошло не так

- Скрипт печатает пути `exit:` и `log:`. Сначала читай лог; строки хода обычно уже показывают причину (отклоненная модель, проблема со входом, упавшая команда).
- Коды выхода: 2 неверные аргументы; 3 Codex ответил вне формата, сырой ответ по пути `json:`; 4 (воркер) ветка или worktree уже есть, смени метку или почисти; 5 (ревью) ревьюить нечего, дифф пустой; 124 лимит времени; 130 и 143 прерывание, Codex тоже остановлен.
- `--dry-run` печатает точную команду Codex и файл промпта, ничего не запуская.
- Codex видит только то, что ему дали: задачу, фокус, файлы для чтения и `~/.agents/AGENTS.md`. Твой `~/.claude/CLAUDE.md` он не читает; проектный `CLAUDE.md` читает, только если в проекте нет `AGENTS.md` (этот запасной вариант включает шаг 5 установки). Если он чего-то «не знал», положи это в фокус или в задачу.
- Codex падает на самом первом запросе: проверь модель в `~/.codex/config.toml`; аккаунт, под которым выполнен вход, должен ее поддерживать.
- Тесты без Codex и без затрат: `bash skills/second-opinion/tests/run.sh` и `bash skills/codex-worker/tests/run.sh`.

## Как это сделано

Эту часть стоит прочитать, если ты делаешь инструменты с агентами.

**Роли.** Человек (Яков) решал, для чего инструмент, что в него входит и что значит «готово». Claude Code был оркестратором: писал скрипты и документацию, раздавал ревью и правки субагентам, запускал настоящий Codex, читал логи. Codex был предметом: каждое утверждение о его флагах и ключах конфига сверялось с установленным бинарником.

**Первый день, в личной настройке.** Связка началась как два личных скилла: ревьюер только на чтение, который отвечает по схеме, и воркер в git worktree. Потом наблюдаемость, потому что прогон Codex, которого не видно, выглядит сломанным: строки хода из потока событий, счетчик `codex:N`, живая таблица.

**Второй день, отчуждение.** Форму сверили с тем, как Андрей Карпати выпускает маленькие репозитории: установщик это текст для агента, без shell-скрипта с ветвлениями; репозиторий читается за один присест; одна команда на пустой машине показывает все целиком (`demo.sh`); один настоящий прогон разобран по шагам (`docs/how-it-works.ru.md`). Скиллы переписаны на английский с путями относительно своей папки, тесты переведены на фальшивый `codex`, чтобы CI гонял их на Ubuntu и macOS бесплатно, поднят сайт. Первый README начинался с архитектуры; человек прочитал и сказал, что никому ничего не понятно, нужно гораздо проще. Его переписали как карту: что говоришь, что происходит, что видишь.

**Через неделю, ревью.** Человек попросил две вещи: ставить сигнал Codex в статус-строку при установке, всегда, и довести репозиторий до состояния, в котором им может пользоваться любой. Условие для статус-строки: не переносить ее целиком, а добавлять именно этот кусок. Это исключает переписывание чужого скрипта, поэтому установщик оборачивает существующую команду, и это можно откатить.

Затем субагент-ревьюер только на чтение прошел репозиторий глазами новичка. Он вернулся с пятью дефектами, которые сломали бы инструмент у других людей, и пятнадцатью помельче. Другой субагент чинил скрипты, начиная с тестов, а оркестратор параллельно правил документацию; файлы у них не пересекались.

**Что поймали ревью и настоящие прогоны.** Выборка, все есть в истории git:

- Ctrl-C останавливал скрипт, но не Codex. GNU `timeout` уводит себя в отдельную группу процессов, а фоновые задания в неинтерактивном bash игнорируют SIGINT, поэтому Codex продолжал работать и тратить квоту до 30 минут. Теперь оба скрипта ловят INT, TERM и HUP, останавливают Codex и записывают `interrupted`.
- Текст установки пользовался `$BRIDGE`, но нигде его не присваивал. Каждый вызов Bash в Claude Code начинается с чистого окружения, а `ln -s` не проверяет цель, поэтому скиллы молча линковались на `/skills/...`. Теперь каждый блок команд начинается с присваивания, а ссылки проверяются.
- «Допиши строку в `~/.codex/config.toml`» для TOML неверно: строка попадает внутрь последней `[таблицы]` файла. Теперь инструкция вставляет ее над первой таблицей.
- Шаблон общего файла инструкций копировался вместе с заполнителями, и оба агента читали бы `Respond in <language>` буквально. Теперь про каждый заполнитель спрашивают, а `grep` доказывает, что ни одного не осталось.
- Скиллы ставились и в Codex, где они запустили бы Codex внутри его же песочницы, без сети, а «второе мнение» пришло бы от той же модели. Этого шага больше нет.
- Промпт уходил в Codex одним аргументом командной строки: виден любому, кто запустит `ps`, и на Linux ограничен 128 КиБ на аргумент. Теперь он идет через stdin.
- Codex перенес веб-поиск из `tools.web_search` в верхнеуровневый `web_search = "live"`, а алиас модели указывал на модель, которой больше нет. И то и другое сверено с самим Codex 0.156.
- Ревью пустого диффа все равно тратило запрос. Теперь скрипт выходит с кодом 5, не вызывая Codex.
- Настоящее демо показало то, чего не видели тесты: в патче воркера едут бинарные `__pycache__/*.pyc`: у одноразового репозитория не было `.gitignore`, а воркер запускал тесты. Воркер уважает `.gitignore`, поэтому демо его получило.
- Настоящее демо еще и падало на первом же запросе по причине, которую не поймает ни один тест: модель, указанная в локальном конфиге Codex, была недоступна аккаунту. Строки хода показали ошибку через четыре секунды, и это аргумент в их пользу.

Статус-строку проверяли так же: поддельный процесс `codex exec` (`exec -a codex perl exec`, без запроса и без затрат) для самопроверки и CI, затем два настоящих агента Codex для доказательства на гифке выше.

**Что из этого взять.** Отчуждение стоит отдельной работы: большая часть дефектов нашлась в тексте установки. Ревью стоит столько, сколько его находок выживает: каждую сверили с кодом или воспроизвели до любых правок. И настоящий прогон находит то, чего не находят тесты: модель, которой нет у аккаунта, папку кеша в патче.

## Agentic Lab

claude-codex-bridge это учебный кейс [Agentic Lab](https://ai-lab-agents.com), лаборатории применения ИИ-агентов в бизнесе, которую ведут Дмитрий Соловьев и Яков Васильев. Участники проходят путь от переписки с моделью до агентных систем, которые доводят задачу до конца: собственный проект, конвейеры данных, быстрые сервисы и интерфейсы, с Claude Code, Codex и Cursor в качестве ежедневных инструментов.

Этот репозиторий показывает один рабочий паттерн целиком: две модели двух компаний, одна оркестрирует, другая ревьюит или исполняет, между ними файлы, решает человек. Поставь, запусти демо, прочитай скрипты.

## Как участвовать

Держи репозиторий таким, чтобы его можно было прочитать за один присест. Новый режим это новый флаг с тестом. Перед изменением прогоняй оба набора тестов; CI гоняет их на фальшивом `codex` на Ubuntu и macOS, плюс установщик статус-строки во временном HOME. `progress.py` скопирован в оба скилла намеренно, правь оба (CI их сравнивает). Документация на английском и русском, меняй обе версии. Гифки рендерятся [VHS](https://github.com/charmbracelet/vhs) из `docs/media/*.tape`.
