# claude-codex-bridge

[![tests](https://github.com/vasilievyakov/claude-codex-bridge/actions/workflows/tests.yml/badge.svg)](https://github.com/vasilievyakov/claude-codex-bridge/actions/workflows/tests.yml) [![license: MIT](https://img.shields.io/badge/license-MIT-d4ff3f?labelColor=0b0b0c)](LICENSE) [![site](https://img.shields.io/badge/site-vasilievyakov.github.io%2Fclaude--codex--bridge-0b0b0c?labelColor=d4ff3f)](https://vasilievyakov.github.io/claude-codex-bridge/?lang=ru)

Ты работаешь в Claude Code. Эта штука добавляет второй ИИ, OpenAI Codex, для двух дел: посмотреть на твой код свежим взглядом и сделать побочную задачу, пока ты занят своей. Codex работает в песочнице и отвечает файлами. Claude читает эти файлы и показывает тебе результат. В твоем проекте ничего не меняется, пока ты не скажешь «да».

Сделано для участников лаборатории [Agentic Lab](https://ai-lab-agents.com). Открыто для всех.

Сайт: [vasilievyakov.github.io/claude-codex-bridge](https://vasilievyakov.github.io/claude-codex-bridge/?lang=ru). In English: [README.md](README.md).

## Что ты получаешь

- **Второе мнение.** Скажи в Claude Code «спроси у Codex второе мнение». Codex читает твои изменения, ничего не трогая, и возвращает список проблем, каждая с файлом и строкой. Claude проверяет каждый пункт по коду и говорит, какие из них настоящие. Двадцать секунд в демо.
- **Воркера.** Скажи «отдай эту задачу Codex». Codex делает ее в отдельной копии твоего репозитория и возвращает патч. Ты смотришь дифф и решаешь. Воркеров может быть несколько сразу.
- **Видимость.** Строки хода в терминале, пока Codex работает, счетчик `codex:N` в конце твоей статус-строки (сколько агентов Codex работает прямо сейчас; ставится при установке), живая таблица во втором окне.

## Установка

Открой Claude Code на своей машине и вставь эту строку:

```
Установи claude-codex-bridge: сначала прочитай https://raw.githubusercontent.com/vasilievyakov/claude-codex-bridge/main/INSTALL.ru.md, затем выполни каждый шаг, подстрой под эту машину, проверь и отчитайся, что изменил.
```

Агент ставит все сам и отчитывается, что изменил. Твои файлы он никогда не перезаписывает. Чтобы сделать руками, пройди [INSTALL.ru.md](INSTALL.ru.md): каждый шаг это команда.

Проверка: открой новую сессию Claude Code и набери `/second-opinion`. Или запусти демо, одна-две минуты, два запроса к Codex:

```
git clone https://github.com/vasilievyakov/claude-codex-bridge
cd claude-codex-bridge
bash demo.sh
```

Нужны Claude Code, [Codex CLI](https://github.com/openai/codex) 0.150 или новее с выполненным входом, git и python3. macOS или Linux.

## Как пользоваться каждый день

| Что ты говоришь в Claude Code | Что происходит | Что ты видишь |
|---|---|---|
| «Спроси у Codex второе мнение по моим изменениям» | Codex делает ревью незакоммиченных изменений, только чтение | Строки хода, затем таблица: каждая находка с вердиктом (подтверждено, опровергнуто, вне области, не проверено) и вопрос, что чинить |
| «Пусть Codex посмотрит план в docs/plan.md» | То же, для документа вместо диффа | Та же таблица |
| «Пусть Codex посмотрит src/billing.py, фокус на округлении» | То же, для названных файлов с фокусом | Та же таблица |
| «Отдай Codex задачу: реализовать parse_date в src/dates.py, тесты в tests/test_dates.py, прогнать pytest» | Codex работает в своей копии репозитория | Статус, сводка, чем он проверял, дифф и вопрос, применять ли |
| «Поспорь с Codex по находке 2: на строке 41 есть проверка» | Продолжается тот же тред Codex | Его ответ |
| «Прибери воркера Codex» | Удаляет копию воркера | Подтверждение |

Два правила. Задача воркеру должна быть полной: что сделать, где, как проверить, что не трогать. Codex не задает вопросов: он делает допущения и перечисляет их. И каждый запуск тратит квоту Codex, поэтому проси ревью после настоящей правки, а не после каждой опечатки.

## Что происходит под капотом

1. Claude пишет задачу в текстовый файл.
2. Скрипт запускает Codex в песочнице: только чтение для ревью, запись в одну отдельную копию для воркера.
3. Codex читает код, может прогнать тесты и отвечает JSON-файлом в фиксированном формате.
4. Скрипт проверяет ответ, кладет его рядом с журналом и печатает пути.
5. Claude открывает каждую находку в коде и отмечает, настоящая она или нет.
6. Исправление возвращается патчем. Claude показывает его и применяет только после твоего слова.

Две модели никогда не разговаривают друг с другом. Все между ними это файл, который можно открыть. Полный разбор с настоящим выводом демо-прогона: [docs/how-it-works.ru.md](docs/how-it-works.ru.md).

## Где что лежит

| Папка | Что внутри |
|---|---|
| `skills/second-opinion/` | Скилл ревью: инструкции для Claude, скрипт, формат ответа, тесты |
| `skills/codex-worker/` | Скилл воркера: то же устройство |
| `extras/` | Сигнал Codex в статус-строке и его установщик (`install-statusline.sh`, обязательный шаг установки); по желанию: живая таблица процессов Codex, шаблон одного файла инструкций, который читают оба агента |
| `demo.sh` | Один настоящий прогон на одноразовом репозитории |
| `INSTALL.md`, `INSTALL.ru.md` | Текст установки для твоего агента |
| `docs/` | Сайт и подробный разбор |
| `~/.cache/second-opinion/`, `~/.cache/codex-worker/` | Все, что породил прогон: промпт, журнал, ответ, патч. Пишут скрипты, не ты |

## Если что-то пошло не так

- Скрипт печатает пути `exit:` и `log:`. Сначала читай журнал.
- Код выхода 2: неверные аргументы. 3: Codex ответил не по формату, сырой ответ лежит по пути `json:`. 4 (только воркер): ветка или worktree уже есть, смени метку или прибери. 124: лимит времени.
- `--dry-run` печатает точную команду Codex и промпт, ничего не запуская.
- Codex видит только то, что ему дали: задачу, фокус, файлы для чтения и общий `~/.agents/AGENTS.md`. Твой `~/.claude/CLAUDE.md` он не читает; проектный `CLAUDE.md` читает, только если в проекте нет `AGENTS.md` (этот запасной вариант включает шаг 5 установки). Если он чего-то «не знал», положи это в фокус или в задачу.
- Тесты без Codex и без затрат: `bash skills/second-opinion/tests/run.sh` и `bash skills/codex-worker/tests/run.sh`.

## Как вносить правки

Держи все читаемым за один присест. Новый режим это новый флаг с тестом. Перед правкой прогони оба набора тестов; CI гоняет их на Ubuntu и macOS с фальшивым `codex`. `progress.py` намеренно скопирован в оба скилла, правь оба. Документация на английском и русском, меняй обе.
